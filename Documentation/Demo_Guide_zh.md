# Week 1 课堂演示指南（约 2–3 分钟）

## 演示前准备

- 用 UE 5.7 打开 `EmberAttractor.uproject`，在启动地图 `/Game/EmberLab/L_EmberLab` 按 **Play**；也可以直接运行项目根目录的 `Play_Lab.cmd`。进入游戏后先点击视口，让键盘和鼠标输入生效。
- 确认画面中橙色粒子是 GPU Sprite 系统（默认目标数 100,000），蓝色粒子是 CPU Mesh 系统（默认目标数 500）。HUD 显示的是目标数量；需要查看实时模拟信息时打开 Niagara Debugger。
- 记住切换键：`0` 基线（两个系统都关闭）、`1` 仅 GPU、`2` 仅 CPU、`3` 两个系统同时运行。按 `[` / `]` 调整当前选中系统的数量预设；数量变化会重置受影响的粒子爆发。按住鼠标左键把粒子吸向鼠标位置；`R` 重置爆发；`F` 开关每八秒重复一次的爆发。
- 若想用控制台指定数值，按波浪号键打开控制台，输入：

  ```text
  ember.Mode 3
  ember.GPUCount 100000
  ember.CPUCount 500
  ```

  GPU 预设为 10k、25k、50k、100k、200k；CPU 预设为 500、1k、2k、3.5k、5k。演示恢复默认组合时使用 `ember.Mode 3`、`ember.GPUCount 100000` 和 `ember.CPUCount 500`。

## 口头演示流程

**0:00–0:30｜说明问题与提案**

“这是 *Niagara at Scale* 第一周的独立原型 Ember Attractor。玩家用鼠标移动吸引点并按住左键，控制测试室里的爆发粒子。它借鉴了《PixelJunk Shooter Ultimate》中由模拟物质驱动玩法的方向，以及《Noita》的热物质表现。课程 Track B 原本要求 boids；这里提出了自定义的余烬吸引玩法，仍需老师接受这个变体。”

**0:30–1:10｜展示两端粒子系统**

“橙色是大量、简单的 GPU Sprite，蓝色是较少、带碰撞模块的 CPU Mesh。热状态和回收事件计划在第二周加入。按 `1`、`2`、`3` 可以分别看 GPU、CPU 和两者同时运行，`0` 是基线。按住左键移动吸引点，观察两类粒子对同一输入的响应。”实际操作模式切换并拖动吸引点。

**1:10–1:40｜展示运行时数量控制**

“数量可以在运行时调整，便于重复不同规模的实验。当前选中系统后按 `]` 增加、按 `[` 减少；粒子爆发会随数量变化重新开始。也可以通过控制台分别设置 `ember.GPUCount` 和 `ember.CPUCount`。”短暂增加或减少数量，再恢复默认值。

**1:40–2:10｜说明本周边界与下一步**

“第一周目标是让两套系统在测试地图里运行，提供运行时数量控制，并完成第一份 profiler capture，这三项已经有运行和采集记录。本机 1080p 合并运行的平均整帧耗时约 3.61 ms，系统 GT/RT 统计合计约 0.565 ms；这些是带 profiler 的初步数据，不能代替课程机房测试。采集截图时的卡顿也保留在报告里。基于粒子状态的计分/回收结果和 GPU 到玩法状态的反馈验证安排在第二周。”打开 [Week1_Status.md](Week1_Status.md) 展示四组测量表。

**2:10–2:30｜交代参考游戏准备**

“作业要求写提案前至少体验或观看两款参考游戏，并记录自己的观察。我的提案列出了《PixelJunk Shooter Ultimate》和《Noita》，但个人体验/观看笔记仍待补齐。”如课前已完成，展示已补充的两条简短观察；未完成时如实说明并列为待办。
